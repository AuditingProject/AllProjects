### How these repos were matched

Evidence for all seven: `program-data.json` → `programCodebases[0].url = https://github.com/gammaswap` ("GammaSwap Codebase"), repeated in the "Notes on assets" section ("All code of GammaSwap can be found at https://github.com/gammaswap"); repos enumerated with `gh api orgs/gammaswap/repos`. Verification used Sourcify (`/v2/contract/42161/<address>?fields=compilation`), whose `fullyQualifiedName` for these deployments literally embeds the `@gammaswap/<repo>` package path:

- `v1-core` — GammaPoolFactory `0xFD51…C20B` → `@gammaswap/v1-core/contracts/GammaPoolFactory.sol:GammaPoolFactory`; also holds `contracts/utils/MinimalBeaconProxy.sol` (asset `0x63c5…dc2d`, on-chain name `MinimalBeaconProxy`) and `contracts/utils/LockableMinimalBeacon.sol` (asset `0xad64…5cCC`, on-chain `contracts/utils/LockableMinimalBeacon.sol:LockableMinimalBeacon`).
- `v1-implementations` — VaultGammaPool `0xbd6e…311c` → `@gammaswap/v1-implementations/contracts/pools/VaultGammaPool.sol:VaultGammaPool`; CPMMMath `0xc5fa…BE03` → `…/contracts/libraries/cpmm/CPMMMath.sol:CPMMMath`; VaultBatchLiquidationStrategy, VaultLiquidationStrategy, VaultShortStrategy and VaultRebalanceStrategy all resolve to `@gammaswap/v1-implementations/contracts/strategies/vault/…`.
- `v1-deltaswap` — DeltaSwapFactory `0xCb85…ffA8` → `contracts/DeltaSwapFactory.sol:DeltaSwapFactory`, DeltaSwapPair `0x755F…fEF0` → `contracts/DeltaSwapPair.sol:DeltaSwapPair`, DeltaSwapRouter02 `0x5FbE…aE1b` → `contracts/DeltaSwapRouter02.sol:DeltaSwapRouter02` — an exact path match for this repo's `contracts/` layout. The sibling `gammaswap/v2-deltaswap` was checked and **rejected**: its files are `DeltaSwapV2Factory.sol` / `DeltaSwapV2Pair.sol` / `DeltaSwapV2Router02.sol`, which do not match the deployed names.
- `v1-staking` — StakingRouter `0xc582…4ae4`, RewardTracker `0xd04F…4088`, RewardDistributor `0x57e4…27C8`, Vester `0xC499…1243`, BeaconProxyFactory `0x3dc7…7477`, BonusDistributor `0x8782…9367` and FeeTracker `0xc964…1e9c` all resolve to `@gammaswap/v1-staking/contracts/<Name>.sol:<Name>`.
- `v1-periphery` — asset 26 "PositionManager (Proxy)" `0x3b72…98b0` is an `ERC1967Proxy` on-chain; its implementation source is this repo's `contracts/PositionManager.sol` (`contract PositionManager`), the only GammaSwap repo defining it.
- `gs-token` — asset "GS" (the GammaSwap ERC20); repo contains `contracts/GS.sol` (`contract GS`), and the repo description is "GammaSwap ERC20 Token".
- `timelock` — GSTimelockController → `@gammaswap/timelock/contracts/GSTimelockController.sol:GSTimelockController`. Note: Sourcify resolves `0x3f7cf127…` (listed in the table as "GS") to `GSTimelockController`, while `0xb08d8bec…` (listed as "GSTimelockController") is a bare `ERC1967Proxy` — the two labels appear swapped in the Immunefi table; both are covered by `timelock` + `gs-token`.

## Out of scope (from the program page)

- Best practice recommendations
- Impact in UniswapV2 code for DeltaSwap fork (Unless such code was materially changed by GammaSwap or used by the GammaSwap contracts)
- Impacts affecting only the state of implementation contracts
- Impacts affecting the value of parameters used to determine whether DeltaSwap will charge a trading fee or not (e.g. liquidityEMA, liquidityTradedEMA, etc.) Because DeltaSwap is set up to always charge a trading fee and the current GammaPool implementation requires that it must always charge a trading fee.

- Airdrop contract is not eligible for medium level bugs.

For critical Smart Contract bugs, the reward amount is 10% of the funds directly affected up to a maximum of USD 40,000. The calculation of the amount of funds at risk is based on the time and date the bug report is submitted. However, a minimum reward of USD 15,000 is to be rewarded in order to incentivize security researchers against withholding a bug report.   

__Repeatable Attack Limitations__

In cases of repeatable attacks for smart contract bugs, only the first attack will be counted, regardless of whether the smart contract is upgradable, pausable, or killable.

__Reward Calculation for High Level Reports__

High smart contract vulnerabilities will be capped at up to 100% of the funds affected. There is a minimum reward of __$5,000 USD__. In the event of temporary freezing, the reward doubles for every additional  5  blocks that the funds or NFTs could be temporarily frozen, rounded down to the nearest multiple of 5, up to the hard cap of USD 10,000.
